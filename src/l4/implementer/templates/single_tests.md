# Phase: SINGLE (add tests that run changed code)
{result_values}
This task answers a finding the verifier reported against the committed work: changed code that no test runs. The finding is in the data block of the proposal that names it by id, the task title cites that id, and the finding lists the functions and modules (`path::function`) whose code the tests must run.
Add tests that run that code and check what it does: you may add new test files, and you may append new tests to this unit's own test files. There is no change to an existing test, no deleted test and no change to non-test code in this task: a test you edit or remove is put back, and a change to production code fails the task. If a subject cannot be tested without changing production code, say so in `notes_for_verifier` and add the tests that you can.
Tag a test with a criterion id ({trace_form}) only when the test checks the outcome that criterion describes; a test that only runs the code carries no id.
If the task cites a criterion (a `C-...` id in its title), the finding is about the tests of code that already does what that criterion says. Add new tests, with new names, that carry that criterion and assert the outcome its scenario names through the interface the design names (a real server, the command, the public function), not a private helper. An edited or removed test is put back, so a test that bypasses the interface stays and its replacement is a new one. At least one of the tests you add must fail by assertion when the function under test answers its zero value (or on the unit's base code); the harness runs that check, and an attempt with no such test fails.
If the task begins with a decision by a human ("Decided by ... in Q-..."), the tests you add MUST assert the behaviour that decision describes. A test that asserts what the code does now, when the decision says that is wrong, is rejected. If the code cannot meet the decision (this task may not change it), add the test that asserts the decision, which fails now, and report status blocked with one question of kind technical that names the test and the decision: the failing test is not kept, and a person answers.
When you are done, run the gate command: every test that passed before must still pass, and every test you added must pass.
