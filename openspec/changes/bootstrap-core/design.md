## Context

SPEC sections 2, 3, 14 and 15 (Part I) and scenarios SCN-CLI, SCN-CFG, SCN-OBS, SCN-DOC (Part II) define this change. Architecture principle P8 (ports and adapters with a `fake` for each) and AD-04 (deterministic orchestrator) require that the foundation be pure and testable: exit codes, outcome rendering, redaction and config validation are pure functions over data; the CLI is a thin shell. Runtime stack is fixed by `openspec/config.yaml`: Python 3.11 or newer, uv, click, pydantic v2, PyYAML, httpx. Evidence labels: `[V]` verified, `[I]` design decision, `[U]` must be confirmed by a test or spike before relying on it.

## Goals / Non-Goals

Goals:
- `uvx --from git+<repo>@<sha> l4 --version` and `l4 doctor` work on a clean shell runner (M1 criterion 1).
- One definition each of exit codes, config models, redactor, outcome schema and check registry that all later changes import.
- Strict, secret-safe configuration: typos exit 2, secrets are never echoed.

Non-Goals:
- Spec detection, providers, ledger, git/worktree, agents, forge, CI template rendering, `l4 init`: other changes. This change only wires their commands as stubs.
- Installing missing tools (`doctor --fix` installs nothing here; installation is the `runner-provisioning` change).
- SANDBOX, SPEC, GIT, FORGE, CI, STATE, MEM and LIVE check bodies: each owning change registers its checks through the registry defined here.

## Decisions

### D1 Package, build and entry point
`pyproject.toml`: `[build-system] requires=["hatchling"]`; `[project] name="l4harness"`, `requires-python=">=3.11"`, dependencies `click>=8.1`, `pydantic>=2.6`, `pyyaml>=6`, `httpx>=0.27`; `[project.scripts] l4 = "l4.cli:main"`; wheel packages `src/l4` with package data `src/l4/schema/*.json`. Dependency group `dev`: `pytest`, `pytest-cov`, `ruff`, `mypy`, `jsonschema`, `types-PyYAML`. Alternatives: setuptools (needs more config for src layout and data files), typer (extra dependency; click is permitted by NFR-004 and already named in the project context).

### D2 CLI shell and lazy dispatch
`l4.cli` defines `main()` calling `cli.main(standalone_mode=False)` and converting exceptions to `ExitCode`. A decorator `common_options` adds `--config`, `--repo`, `--log-format`, `-v/-q` to every command (SPEC: all commands) and builds `AppContext(repo: Path, config_path: Path | None, log_format: str, verbosity: int)`. Each command body calls `commands.dispatch(name, app, **kwargs)`. `l4.commands.HANDLERS: dict[str, str]` maps command names to `"module:function"` strings. The full table is fixed here so every change names its handler identically (cross-change review 2026-10-03); a change delivers a command by creating the named module and function, never by editing `cli.py`:

| Command | Handler | Owning change |
|---|---|---|
| `init` | `l4.init.init:run_init` | forge-and-ci |
| `doctor` | `l4.doctor.run:run_doctor` | bootstrap-core |
| `plan` | `l4.planner:run_plan` | simulation-harness |
| `run` | `l4.orchestrator:run_command` | implementer-tdd-loop |
| `status` | `l4.state.status:run_status` | state-vcs-locks |
| `probe` | `l4.availability.fallback:run_probe` | agent-factory |
| `verify` | `l4.verifier.ladder:run_verify` | verifier |
| `archive` | `l4.archive:run_archive` | forge-and-ci |
| `questions` | `l4.specs.questions:run_questions` | spec-providers |
| `lessons` | `l4.memory.cli:run_lessons` | memory-lessons |
| `simulate` | `l4.sim.runner:run_simulate` | simulation-harness |

Handlers take `(app: AppContext, **options)` and return an `ExitCode`. `dispatch` imports lazily; only `ModuleNotFoundError` whose `.name` equals the handler module (or a parent package of it) is treated as "not yet implemented" (stderr `<command>: not yet implemented`, exit 2); any other import error is a real bug and surfaces as exit 1. Alternative: eager imports of all modules (breaks while modules do not exist; couples every change to `cli.py`). `l4 ci map-exit` is implemented here as a real command (pure function `exitcodes.map_exit`) because it is part of the exit-code contract; the CI templates that call it belong to `forge-and-ci`.

### D3 Exit codes
`exitcodes.ExitCode(IntEnum)` with members OK=0, INTERNAL_ERROR=1, USAGE_ERROR=2, DOCTOR_FAILED=3, CONTINUE=10, AWAITING_HUMAN=11, WAITING_CAPACITY=12, HALTED=13, REJECTED=14. `SEVERITY_ORDER = (1, 2, 3, 13, 14, 11, 12, 10, 0)`; `most_severe(codes: Iterable[int]) -> ExitCode` returns the first member of `SEVERITY_ORDER` present, `OK` for empty input, and raises `ValueError` for a code outside the table. `class L4Exit(Exception)` carries a code for handlers. `map_exit(code, platform) -> MappedExit(annotation: str | None, exit_code: int)`: github maps 0 to (None, 0); 10, 11, 12 to (`::warning::...` or `::notice::` for 10, 0); others to (`::error::...`, 1); gitlab returns (annotation line, code) unchanged. The GitHub annotation level for 10 is `::notice::` and for 11/12 `::warning::` [I; SPEC says `::warning::`/`::notice::` without naming which]. Unknown code: `map_exit` raises `ValueError`; the command exits 2.

### D4 Outcome
`outcome.py`: pydantic models `UnitOutcome` (fields exactly as SPEC 2.2: `unit, phase_before, phase_after, tasks{done,total}, open_questions, verdict, profiles, cost_usd, iteration, pr_url, retry_after, continuation`) and `Outcome(schema="l4/outcome@1", run_id, harness_version, exit_code, units)`. `continuation` is `Literal["not_needed","dispatched","failed"]`; `exit_code` is validated against `ExitCode`. `new_run_id(now, rng)` returns `r-YYYYMMDDTHHMMZ-xxxx` (4 hex characters). `write_outcome(outcome, out_dir, redactor)` writes to a temporary file in `.l4-out/` then `os.replace`. `write_ci_outputs(outcome, env, out_dir, *, actionable: Sequence[str])` appends `exit_code=`, `units=<JSON array of the actionable unit ids>`, `phases=<JSON object unit to phase_after>` to the file named by `$GITHUB_OUTPUT` when set, and always writes `.l4-out/l4.env` with `L4_EXIT`, `L4_UNITS_ACTIONABLE` (count of `actionable`) and `L4_PHASES` (comma separated `unit=phase`) [I: SPEC names the keys but not their value formats]; the caller supplies `actionable` (the planner for `plan`, the orchestrator for `run`). `outcome_json_schema()` produces `src/l4/schema/outcome.schema.json`. A wrapper `with_outcome(command_name)` in `cli.py` writes the outcome in a `finally` block for `run, verify, archive, plan`, using `exit_code=1` for unexpected exceptions.

### D5 Configuration models
`config/schema.py` defines `L4Config(BaseModel)` with `model_config = ConfigDict(extra="forbid")` and 21 section models: `version` (Literal[1]), `HarnessCfg`, `SpecCfg` (`OpenSpecCfg`, `KiroCfg`), `SddCfg`, `TddCfg`, `OddCfg`, `GatesCfg` (`TestGate`, `E2eGate`, `ServeCfg`, `ExtraGate`), `SandboxCfg` (`CacheCfg`), `profiles: dict[str, Profile]`, `RolesCfg`, `AvailabilityCfg`, `ImplementerCfg`, `ClarifierCfg`, `VerifierCfg` (`PlaywrightCfg`, `S1Cfg`, `PanelCfg`), `ArchiveCfg`, `MemoryCfg` (`SerenaCfg`), `ForgeCfg` (`GithubAppCfg`), `LocksCfg`, `CiCfg`, `BudgetsCfg`, `ObservabilityCfg`. Defaults are exactly those printed in SPEC 3.2; the list defaults (`test_globs`, `redact_env`, ...) live in `config/defaults.py` as module constants. `Duration` is a `str` subtype validated by `^\d+(s|m|h)$` with `to_seconds()`; `auto | list` and `auto | bool | duration` unions are `Union[Literal["auto"], ...]`. `Profile` is ONE model with all fields optional (`adapter, backend, model, auth, min_version, max_concurrency, options, vendor, base_url, api_key_env, engine`) and no mutual-exclusion validator, because SCN-CLI-07 requires doctor CFG-002 (exit 3) to report "both adapter and backend", not the loader (exit 2). `harness.commit` is `Optional[str]` validated by `^[0-9a-f]{40}$`; the `<40-hex sha>` in SPEC is an example, not a default [I]. Two keys beyond SPEC 3.2 are part of the schema because later changes need them in M1 and `extra="forbid"` would otherwise reject a config that uses them: `ci.self_provision: Literal["auto", True, False] = "auto"` (runner-provisioning) and `clarifier.s1_standin: Literal["none", "llm_boolean"] = "none"` (clarification-loop); both are listed in the task 2.20 SPEC amendment. `Profile.api_key_env` is accepted on adapter profiles as well as backend profiles (agent-factory D6). Alternatives: a discriminated union on `adapter`/`backend` (cannot represent the invalid "both" state doctor must report); dataclasses (no JSON Schema generation).

### D6 Loader, precedence, errors
`load_config(repo, *, config_path=None, environ=os.environ, cli_overrides=None, source=None) -> LoadedConfig(config, raw, secret_findings, source_ref)`. Pipeline: (1) `ConfigSource.read()` returns text (`WorkingTreeSource(path)` in M1; `GitRefSource(repo, ref, ".l4/config.yaml")` using `git show <ref>:<path>` in M2); a missing file means defaults (`version: 1`) [I]; (2) `yaml.safe_load`; (3) `scan_literal_secrets(raw)` over the raw tree; (4) apply env overrides: a variable `L4_<A>__<B>` with at least one `__` sets path `a.b` (keys lower-cased, value parsed with `yaml.safe_load`); variables without `__` (`L4_FORGE_TOKEN`, `L4_CACHE`, `L4_UNIT`, ...) are never overrides [I; SPEC does not give the mapping]; (5) apply `cli_overrides` (dotted path to value; only `--time-budget` maps to `ci.time_budget` in v1); (6) `L4Config.model_validate`. Failures raise `ConfigSchemaError(issues: list[ConfigIssue])` (unknown key, type error, bad `version`), each issue `ConfigIssue(path: str, message: str, suggestion: str | None)` rendered as `unknown key 'verifer' at $ (did you mean 'verifier'?)` using `difflib.get_close_matches(key, allowed, n=1, cutoff=0.7)`. Pydantic's `input` field is never copied into messages (values could be secrets). If `secret_findings` is non-empty the loader raises `ConfigSecretError(findings, schema_issues)` instead; findings hold only the path and rule name. Exit mapping (resolves the SCN-CLI-04 / SCN-CLI-05 tension): schema errors exit 2 in every command including `doctor`; secret errors exit 2 in every command except `doctor`, where they are reported as CFG-001 and exit 3. Precedence of the two when both occur: the secret finding wins, so SCN-CLI-05 (where `api_key` is also an unknown key) exits 3 and the unknown-key issue is listed in the same CFG-001 message.

### D7 Secret detection in config
`config/secrets.py`: `scan_literal_secrets(tree) -> list[SecretFinding(path, rule)]`. Rules: (a) the value matches a token shape from `redact.TOKEN_SHAPES`; (b) the key name matches `(?i)(api[_-]?key|token|secret|password|passwd|private[_-]?key)$` and does not end in `_env`, and the value is a non-empty string; (c) any `*_env` key whose value is not `^[A-Za-z_][A-Za-z0-9_]*$` is reported with rule `env-name-invalid`. Rule (b) means an unknown key such as `api_key` is flagged as a secret even though schema validation would also reject it. False-positive guard: values that are themselves env-var-like names are fine under `*_env` keys only.

### D8 Published schema
`config/jsonschema.py::build_config_schema()` returns `L4Config.model_json_schema()` post-processed so every object has `additionalProperties: false`, with `$id` `https://schemas.l4harness/config.schema.json` [I] and `title`. The committed copy is `src/l4/schema/config.schema.json` (ships in the wheel; SPEC names it `l4harness/schema/config.schema.json`, meaning "inside the l4harness distribution"). `python -m l4.config.jsonschema --write` regenerates it; the drift test compares bytes.

### D9 Semantic checks and trust
`config/validate.py`: `check_role_chains(cfg) -> list[Issue]` (paths such as `roles.implementer[1]`), `check_profile_kinds(cfg)` (both or neither of adapter/backend, path `profiles.<name>`), `check_independence(cfg) -> list[Issue]`. Independence: `union = {profile.vendor for p in roles.implementer}`; `different_vendor`: eligible verifier/judge profiles have vendor not in `union`; `different_model`: model not in the set of implementer models; `none`: always eligible; fail when `roles.verifier_agent` or `roles.judges` has no eligible profile, naming the role path. A profile without `vendor` counts as vendor `unknown` and is never eligible under `different_vendor` [I]. `config/trust.py`: `UnitOrigin = Literal["base", "human_branch_new", "human_branch_edit", "harness"]` and `unit_authorized(origin, cfg) -> Decision(allowed: bool, reason: str)`: `human_branch_new` is allowed only with `spec.allow_branch_specs`; the others always. `protected_path_changes(changed_paths) -> list[str]` returns paths under `.l4/**` for the PR body. The router (simulation-harness `planner.py`) calls `unit_authorized`; the git ref read is M2 (needs the `vcs` module from state-vcs-locks for ref resolution; until then the working tree file is used and the base-ref reader is injected).

### D10 Redaction and logging
`redact.py`: `TOKEN_SHAPES` is an ordered list of `(kind, compiled_regex)`: `sk-ant-[A-Za-z0-9_\-]{16,}`, `sk-[A-Za-z0-9_\-]{16,}`, `gh[pous]_[A-Za-z0-9]{20,}` (kinds `github-token`), `github_pat_[A-Za-z0-9_]{20,}`, `glpat-[A-Za-z0-9_\-]{16,}`, `glptt-...`, `gldt-...`, JWT `eyJ[A-Za-z0-9_\-]+\.eyJ[A-Za-z0-9_\-]+\.[A-Za-z0-9_\-]+`, `mk_agent_[A-Za-z0-9]{16,}`, PEM `-----BEGIN [A-Z ]*PRIVATE KEY-----[\s\S]*?-----END [A-Z ]*PRIVATE KEY-----` [I: minimum lengths chosen to avoid `sk-learn`; SPEC gives prefixes only]. `Redactor(values: Mapping[str, str])` is built by `Redactor.from_config(cfg, environ)` from `observability.redact_env` plus every `*_env` value found in the raw config; values shorter than 8 characters or empty are skipped; longer values are replaced first. API: `redact_text(s) -> str`, `redact_obj(o)` (recursive over dict, list, str), `find_secrets(text) -> list[SecretFinding(kind, start, end)]` (no value), `rotation_notice(findings) -> str`. `log.py`: `EventLog(run_id, log_dir, redactor, console_stream, verbosity, json_console)`; `emit(type, *, unit=None, role=None, msg=None, **fields)` validates `type` against `^[a-z]+(\.[a-z_]+)+$`, assigns `seq` (thread-safe counter), writes the JSON line (`ts` ISO-8601 UTC) and, when `msg` is given or the type is a decision type, the console line `[l4] <role or phase>: <msg>`. `DURABLE_EVENT_TYPES` holds the section 12.1 minimum set so the ledger writer (state-vcs-locks) can reuse the same emitter. `-q` shows decision, warning and error lines only; `-v` adds debug. A `logging.Filter` adapter routes stdlib `logging` through the same redactor. `cli.py` emits `run.started` and `run.finished(exit_code)`.

### D11 Cost
`cost.py`: `Usage(input_tokens, output_tokens, cached_tokens, cost_usd | None)`; `account(usage, model, price_table, warn) -> CostDelta(usd | None, source: "reported"|"price_table"|"unknown")`. USD reported wins; else tokens times `price_table[model]` (`input`, `output` USD per million tokens; cached tokens priced as input [I]); else `None` plus one warning per profile per run. `TOKENS_ONLY_ADAPTERS = {"codex"}` [V per SPEC for Codex] is read by doctor COST-001; agent-factory extends it.

### D12 Doctor
`doctor/registry.py`: `@dataclass(frozen=True) Check(id, title, severity: Severity | Callable[[L4Config], Severity], scopes: frozenset[Scope], run: Callable[[DoctorContext], CheckResult], fix: Fix | None = None, unit_aware: bool = False)`, `Severity = Literal["error","warn","info"]`, `Scope = Literal["ci","local","live"]`, `CheckResult(status: Literal["pass","fail","skip"], message: str, fix_hint: str | None = None, cost_usd: float = 0.0, severity_override: Severity | None = None)`. `register(check)` raises `DuplicateCheckError` on a repeated id. `run_checks(ctx, *, ci, live, unit) -> list[CheckOutcome]` filters: `live=False` drops `live` scope; `ci=True` keeps only `ci` scope; `unit` passes the unit to unit-aware checks. `--ci` rule [I; SPEC leaves the filter undefined]: a check is in the `ci` scope unless its owner declares it `local`-only; ENV, CFG, SANDBOX, SPEC, FORGE-001/002, CI-* are `ci`+`local`; GIT-* maintenance checks and STATE-001 are `local` only (their fixes mutate local state). `report.py` renders the table and `l4/doctor@1` JSON `{schema, ok, exit_code, checks: [{id, severity, status, message, fix}], probe_cost_usd}`; `ok` is false when any error-severity check failed. `fix.py::apply_fixes` runs each failing check's registered `Fix(kind, scope, apply: Callable[[DoctorContext], FixOutcome])` only if its `kind` is in `SAFE_FIX_KINDS = {prune, release, delete, create, rebuild-mirrors, re-render, install}` (`install` = user-local tool install of runner-provisioning, L4-PRV-004/005), then re-runs the fixed checks so the report and exit code reflect the state after fixing (a successful `install` turns ENV-003 into a pass in the same run), then runs `git diff --quiet` and `git diff --cached --quiet` over tracked files and fails with exit 1 listing changed files. `FixScope = Literal["provision", "repo"]`; with `--ci` only `provision` fixes run (runner-provisioning D5). `registry.attach_fix(check_id, fix)` lets another change hang a fix on a check it does not own (runner-provisioning attaches `install` fixes to ENV-001, ENV-003, ENV-004) without registering a second check. `DoctorContext` carries `repo, cfg, env, which(name), run(argv, timeout)` so tests inject fakes; no check calls `subprocess` directly. Checks: `checks_env.py` ENV-001 (`sys.version_info >= (3,11)` and `which("uv")`), ENV-002 (`git --version`, parse `(\d+)\.(\d+)`, >= 2.40), ENV-003 (`node --version` >= 20.19 and `$L4_CACHE/tools/openspec-<spec.openspec.version>/node_modules/.bin/openspec --version` equals `spec.openspec.version`, the harness-owned prefix of L4-OSP-001; active when `spec.frameworks` is `auto` and `<repo>/<spec.openspec.root>` is a directory, or lists `openspec`; change 2's detector replaces this test later), ENV-004 (adapter binary table `ADAPTER_BINARIES = {"claude-code": "claude", "codex": "codex", "opencode": "opencode", "kiro-cli": "kiro-cli"}` with `--version` parsing; agent-factory adds the `command` and `acp` entries to this table, it registers no second ENV-004; `<binary> --version` output format is [U] and is confirmed by the `spikes` change; severity rule: error when the profile is index 0 of a required chain (`implementer, verifier_agent, judges`) or no profile of a required chain is usable, else warn), ENV-005 (credential names from `l4.config.validate.credential_env_names(profile)`, the one table every change uses (agent-factory `build_env`, sandbox-security `build_agent_env`, runner-provisioning readiness): `api_key_env` when set; else claude-code `api_key` -> `ANTHROPIC_API_KEY`, `subscription` -> `CLAUDE_CODE_OAUTH_TOKEN` (optional, stored login also counts); codex -> `CODEX_API_KEY`; kiro-cli -> `KIRO_API_KEY`; opencode by model prefix `openrouter/` -> `OPENROUTER_API_KEY`, `anthropic/` -> `ANTHROPIC_API_KEY`, `openai/` -> `OPENAI_API_KEY`; `auth: subscription` passes when the first `sandbox.credential_paths[adapter]` entry exists or the token variable (`CLAUDE_CODE_OAUTH_TOKEN`) is set), ENV-006 to ENV-008 (warn; skipped when the feature is off; `laya` import and checkpoint cache path [U]; `playwright --version` and browsers path [U]; `gitleaks version`; `serena --version` against `memory.serena.version` [U]), CFG-001 to CFG-004 in `checks_cfg.py` calling `load_config` and `config/validate.py`, COST-001 in `checks_cost.py`. COST-001 is not in the SPEC table; it is the check SCN-OBS-02 requires ("doctor reports ...") and SPEC.md must be amended in this change (definition of done item 4). The loader result is computed once per doctor run and shared via `DoctorContext.loaded`. Check discovery: `run_doctor` imports `l4.doctor.registry.CHECK_MODULES` (`checks_env`, `checks_cfg`, `checks_cost`, `checks_spec` (spec-providers), `checks_git`, `checks_state` (state-vcs-locks), `checks_agents` (agent-factory), `checks_sandbox` (sandbox-security), `checks_ci`, `checks_forge` (forge-and-ci), `checks_memory` (memory-lessons), `checks_provision` (runner-provisioning)) with the D2 lazy rule: a `ModuleNotFoundError` for exactly that module means the owning change has not landed and is skipped; any other import error is exit 1. Each module registers its checks (and `attach_fix` calls) at import.

`src/l4/commands.py`, `src/l4/redact.py`, `src/l4/cost.py`, `src/l4/config/{secrets,validate,trust,jsonschema}.py`, `src/l4/doctor/{report,run}.py`, `src/l4/schema/`. They keep the files named in the map small and single-purpose.

## Risks / Trade-offs

- [U] `--version` output of agent CLIs (ENV-004) differs per tool; mitigated by a per-adapter regex table and the `spikes` change recording real outputs; unparsable output yields a `warn` not a crash.
- [U] Exact `L4_*` override grammar is not in SPEC; the double-underscore rule is documented in `--help` and in the JSON Schema description; it can be changed before first release without breaking files.
- Two different exit codes (2 and 3) for invalid configuration under `doctor`; documented in D6 and in the CLI help so CI authors are not surprised.
- Over-eager secret detection (rule b) could flag benign keys such as `token_env`-adjacent names; mitigated by the `_env` exclusion and by reporting only path and rule so the operator can fix quickly.
- Redaction by value of short secrets is skipped (under 8 characters) to avoid corrupting logs; very short secrets are therefore only protected by key-name rules.
- Lazy dispatch hides import errors if mis-scoped; mitigated by the exact-module match and a test that every handler string resolves once its module exists.
- `l4 ci map-exit` overlaps the CI integration domain (change 9); ownership of the pure mapping and the command is here, the templates calling it are there.

## Migration Plan

New package; nothing to migrate. Rollback is deleting the package. Later changes replace stubs by adding the handler module named in `commands.HANDLERS`.
