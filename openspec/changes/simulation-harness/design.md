## Context

SPEC section 17 (L4-SIM-001 to L4-SIM-004), section 23.14 (SCN-DRY, SCN-SIM), section 2.1/2.2 (`plan`, exit codes), section 16.4 (sweeper duties) and section 12.0 (lifecycle table) define this change. Evidence labels: `[V]` verified, `[I]` design decision, `[U]` to be confirmed by a test or spike.

Two facts shape the scope. First, SPEC section 21 lists change 4 (this one) before the agent factory (5) and the orchestrator (`src/l4/orchestrator.py`, change 6), yet SCN-SIM scenarios drive "the real orchestrator". Second, there is no `L4-DRY-*` requirement; the DRY scenarios hang off L4-SIM-001 and `l4 plan` has no requirement of its own beyond L4-CLI-001 (bootstrap-core).

## Goals / Non-Goals

Goals:
- A runner and fakes that later changes use to add their own built-in scenarios without touching the runner.
- Deterministic runs: same inputs give identical event sequences once timestamps are removed (L4-NFR-003).
- `l4 plan` that a CI router can call (exit 0, JSON) and `--dry-run` machinery that provably changes nothing.
- A skeleton driver that runs `happy-openspec` and `happy-kiro` end to end with fakes, real git and real gates, clearly labelled as such.

Non-Goals:
- The real orchestrator, agent adapters, forge implementations, verifier (changes 5, 6, 8, 9). The 19 other built-in scenarios are registered as pending with their owners; they are delivered by those changes.
- Claiming the SPEC section 21 exit criterion "happy-openspec, happy-kiro pass with fakes" with the real orchestrator. With the skeleton driver the criterion is met only provisionally; it is re-run with `driver: orchestrator` by change `implementer-tdd-loop` (task named in its tasks.md) and not closed before.
- Rendering CI files (change 9); `--with-repo-config` calls the renderer when present and reports `ci-render: pending` otherwise.

## Decisions

### D1 Fakes are scripted, port-shaped, and local-typed
`sim/types.py` mirrors the SPEC 8.1 dataclass field names (`SimRunRequest`, `SimRunResult`, `SimUsage`, `SimStructuredResult`) because the port definitions (`agents/base.py`, `llm/base.py`, `forge/base.py`) belong to later changes and ports are consumed structurally (Protocol). `sim/fakes.py`: `ScriptedAgent(name="fake")` with `capabilities()`, `probe(profile, step, ctx)` and `run(req)`; `ScriptedBackend.complete_structured(...)`; `FakeForge` implementing exactly the method names of forge-and-ci's `l4.forge.base.Forge` protocol (design D4 there: `whoami`, `ensure_labels`, `find_pr`, `get_pr`, `list_prs`, `create_pr`, `update_pr`, `set_managed_labels`, `upsert_sticky_note`, `set_commit_status`, `list_pipeline_jobs`, `user_can_write`, `approvals`, `dispatch_continuation`, `merge_pr`, `delete_branch`) so forge-and-ci's conformance suite (its task 2.13) runs against it unchanged; it records and counts calls (the simulation asserts zero `merge_pr` calls under `merge_policy: human`) and keeps a `pushes` log; `FakeClock(now)` with `advance()`. Change `agent-factory` wraps `ScriptedAgent` as `agents/fake.py` and aliases the sim types to its own dataclasses. Alternative: wait for ports first (blocks this change on 5 and 9, contradicting the delivery order).

### D2 Scenario model and fixtures
`sim/scenarios.py`: pydantic models with `extra="forbid"`: `Scenario(name, fixture, config: dict, profiles: dict[str, ProfileScript], judges: dict[str, JudgeScript], s1: S1Script, expect: Expect)`; `ProfileScript(probe: ProbeScript | None, steps: list[Step])`; `Step(when: When(phase, task), write: dict[str, str], result: dict, delay_s: float = 0)`; `Expect(exit_code, final_phase, events_include: list[dict], trailers_include: dict[str, str])`. `@fixture:<file>` values are resolved by `resolve_payloads(scenario, fixture_dir)` to file contents (unresolved reference raises `ScenarioError` before anything is created). Fixture directory layout: `src/l4/sim/builtin/fixtures/<name>/repo/` (seed tree copied into the clone) and `.../payloads/` (files referenced by `@fixture:`). The SPEC says scenarios live under `tests/scenarios/*.yaml`; built-in scenarios must also run from an installed wheel (`l4 simulate --all --with-repo-config` in a user repo, L4-SIM-004), so the canonical YAML is packaged at `src/l4/sim/builtin/scenarios/*.yaml` and `tests/scenarios/` holds test-only scenarios (expectation mismatch, malformed) [I; deviation from the implementation map, documented in README]. Fixture repos use the Python stdlib `unittest` only (gate `python -m unittest discover -s tests`), so no third-party tooling is needed.

### D3 Isolated remote and deterministic git
`sim/remote.py::SimRepo.create(root: Path, fixture: str, seed: int) -> SimRepo(remote: Path, clone: Path)` runs `git init --bare`, copies the fixture, commits with fixed `GIT_AUTHOR_NAME/EMAIL`, `GIT_COMMITTER_*`, `GIT_AUTHOR_DATE/GIT_COMMITTER_DATE` derived from the `FakeClock` and `-c commit.gpgsign=false`, and pushes `main`. Every git call goes through state-vcs-locks' hardened `l4.vcs.git.Git(repo, env=...)` (which adds `core.hooksPath=/dev/null`, `core.fsmonitor=false`, `protocol.ext.allow=never`), because that change's `test_no_direct_git_subprocess` forbids spawning git elsewhere under `src/l4`. Because dates and identities are fixed, commit SHAs are deterministic for equal content [I; verified by SCN-SIM-01 test]. `SimRepo.cleanup()` removes the temp root unless `keep`. Real git is required (git >= 2.40 is already a doctor check).

### D4 Runner, drivers, events
`sim/runner.py`: `run_scenario(scenario, *, driver, keep=False, repo_config=None, seed=0) -> ScenarioResult(status: "pass"|"fail"|"pending", driver: str, exit_code, final_phase, events: list[dict], mismatches: list[Mismatch], temp_root: Path | None)`. `Driver` is a Protocol: `run(ctx: SimContext) -> DriverResult(exit_code, final_phase)`, with `SimContext(clone, remote, config: L4Config, agents: dict[str, ScriptedAgent], backends: dict[str, ScriptedBackend], forge: FakeForge, clock, events: EventLog, scenario)`. `resolve_driver()` returns `l4.orchestrator:simulate_driver` when importable and the skeleton otherwise; the result field `driver` is `"orchestrator"` or `"skeleton"`. `sim/skeleton.py::SkeletonDriver` implements only the happy edges of the section 12.0 table: `intake -> ready -> implementing -> implemented -> verifying -> verified -> in_review`, per task a red step (agent writes tests, targeted gate must fail) and a green step (agent writes code, gate must pass), one commit each with `[skip ci]`, made through `l4.vcs.git.Git.commit` with `l4.vcs.trailers.CommitTrailers` (mandatory `L4-Unit`, `L4-Run`, `L4-Iteration`, `L4-Phase`, plus `L4-Task` and `L4-TDD`), task marker set through the spec-provider marker writer, judge verdict from the scripted backend, a draft PR on the fake forge marked ready at `in_review`, exit 0. It raises `SkeletonLimit` for any scenario step outside that path, which the runner reports as `pending` (not pass) [I]. Events are collected through `EventLog` (bootstrap-core) with a `RecordingSink`; `normalize_events(events)` drops `ts` and replaces the temp root prefix in strings with `<tmp>` so two runs compare equal.

### D5 Expectation evaluation
`compare_expect(expect, result) -> list[Mismatch]` checks `exit_code`, `final_phase`, each `events_include` entry as a subset match on event fields in order of appearance, and `trailers_include` against all commits of the unit branch (`git log --format=%B` parsed for trailers). `format_mismatches(mismatches, events)` prints `expected` versus `actual` lines per field and the first event whose type/fields diverge (the first expected event not found, with its nearest predecessor). `l4 simulate` exits 1 when any scenario fails; pending does not change the exit code.

### D6 Planner
`planner.py`: `UnitFacts(unit, framework, phase: str | None, tasks_total, tasks_done, has_pass_record, open_blocking_questions, answers_unblock, retry_after, resume_requested, inputs_changed, pr_state: "none|open|merged|closed", origin: UnitOrigin)`; `PlanEntry(unit, phase, next_action, actionable, reason, retry_after, availability)`; `Plan(schema="l4/plan@1", run_id, entries, duties)`. `next_action` is a pure function of `phase` and facts following section 12.0: no phase and pending tasks, `intake`, `ready`, `implementing`, or `awaiting_human` with `answers_unblock` give `implement`; `clarifying` gives `clarify`; no phase with all tasks done and no PASS record, `implemented`, `verifying` give `verify`; `fixing` gives `fix`; `verified` gives `hand_off`; `halted`/`escalated` with `resume_requested` and `waiting_capacity` after `retry_after` give `resume`; `in_review`, `archived`, `merged`, `abandoned` and the remaining phases give `none` with a `reason` (`rejected: inputs unchanged`, `halted: needs l4 resume`, `awaiting_human: no new answers`, `waiting_capacity until <ts>`, `in_review: waiting for merge`). `actionable = next_action != "none"`. Entries are sorted by unit id; JSON is dumped with sorted keys and no timestamps in the body except `retry_after` copied from state, so two runs are byte-identical (L4-NFR-003, tested here). Units whose origin is not authorized by `config.trust.unit_authorized` get `next_action: none`, `reason: spec not approved (merge to base branch)` (SCN-CFG-02 end to end). `UnitSource` Protocol: `list_units(repo, cfg) -> list[UnitFacts]`; `LiveUnitSource` composes spec-providers' `l4.specs.detect.collect_units(repo, spec_cfg, registry)`, `provider.tasks(unit)` and `l4.specs.questions` (`is_answered`, `blocked_tasks`, for `open_blocking_questions` and `answers_unblock`) with state-vcs-locks' `l4.state.ledger.read_ledger(unit_dir)` and `l4.state.fold.fold(events)`; `StaticUnitSource` is used by tests. `run_plan(app, unit, json, probe, sweep, detailed_exitcode) -> ExitCode` loads config (exit 2 on error), computes the plan, writes `outcome.json` (units = non-terminal units; `phase_before == phase_after`) and CI outputs with `actionable=[...]` (bootstrap-core `write_ci_outputs`), prints a table or JSON, and returns `exitcodes.plan_exit_code(len(actionable), detailed_exitcode)`.

### D7 Availability in plan and dry-run
`AvailabilityView` Protocol: `cached(profile) -> "usable"|"cooling"|"exhausted"|None` and `probe(profile) -> status`. `NullAvailability` returns `None` (rendered `unknown`) and never probes; `--probe` switches to the real view supplied by `availability/` (change 5); a profile without a cached result is `unknown` (SCN-DRY-02). Plan JSON carries `availability: {profile: status}` for the chain heads of the roles the next action needs.

### D8 Sweep
`plan --sweep` appends `Duty(kind, unit, detail, done: bool)` records. The duty-kind vocabulary is fixed here and used verbatim by forge-and-ci: `resume_waiting_capacity` (retry_after passed), `resume_expired_lease`, `detect_merged_or_closed_pr`, `refresh_moved_base`, `honour_resume_label`, `rerun_intake`, `repair_mirrors` (section 16.4). `SweepPort` is one method, `run(plan: Plan, *, dry_run: bool) -> list[Duty]`: the port both detects (it needs forge calls the pure planner does not have) and executes the duties and returns what it did. `run_plan` resolves the real port lazily from `"l4.ci.sweeper:Sweeper"` (forge-and-ci) with bootstrap-core's `ModuleNotFoundError` rule; when absent it lists `sweep: pending` and changes nothing. In simulation a port built on `FakeForge` + `FakeClock` is injected. Without `--sweep` no duty is listed and the port is never called.

### D9 Dry-run
`sim/dryrun.py`: `DryRunViolation(Exception)`; `DryRunEffects` implements the effects interface the orchestrator uses for every side effect (`git_write`, `git_push`, `forge_write`, `acquire_lock`, `invoke_agent`, `invoke_llm`, `write_repo_file`, `write_cache`, `spawn`): each raises `DryRunViolation` after recording the attempt; only `write_out(path)` below `.l4-out/dry-run/<run-id>/` is allowed. `DryRunSession(run_id, repo, redactor)` offers `record_prompt(unit, step, text)` (file `.l4-out/dry-run/<run-id>/<unit>/<step>.md`, redacted), `record_command(argv, env)` (printed with redacted env values), `decision_table(entries)` and `would_exit(code)` printing `would exit <n>`. `snapshot_state(repo, cache_dir) -> str` hashes `git for-each-ref`, `git status --porcelain=v2`, the tree of tracked and untracked files (excluding `.l4-out/`), and the cache directory listing; tests assert equality before and after. `l4 run --dry-run`, `l4 verify --dry-run` and `l4 init --dry-run` obtain `DryRunEffects` from `DryRunSession.effects`; composing it with the prompt renderers and step lists is done by their owning changes (implementer-tdd-loop, verifier, forge-and-ci) and this change tests it with a fake step provider. A `DryRunViolation` that escapes a command maps to exit 1 (internal error) [I].

### D10 Built-in registry
`sim/builtin/manifest.py::BUILTIN: dict[str, BuiltinEntry(owner_change, file | None)]` lists the 21 names of L4-SIM-003 with owners [I; derived from SPEC section 21 exit-criteria column, the two archive scenarios assigned to forge-and-ci]: `happy-openspec`, `happy-kiro` to simulation-harness; `quota-fallback`, `midrun-limit-fallback`, `all-cooling-waiting-capacity` to agent-factory; `stuck-clarifier-answers`, `stuck-human-answers`, `human-overrides-consumed-answer` to clarification-loop; `verify-fail-fix-pass`, `fix-rounds-exhausted-escalate`, `spec-gap-adds-scenario`, `s1-disagreement-needs-human`, `judge-error-fails-closed` to verifier; `red-not-failing-rejected`, `test-weakening-detected`, `protected-file-reverted` to implementer-tdd-loop; `crash-mid-task-resume`, `lock-contention` to state-vcs-locks; `time-budget-continuation`, `archive-refuses-incomplete`, `base-branch-moved-conflict` to forge-and-ci. An entry is `ready` when its YAML exists in `builtin/scenarios/`, else `pending`. `l4 simulate --all` runs the ready ones, lists pending ones with owners, exits 0 unless a ready scenario fails. The release gate is a pytest test marked `release` (`test_no_pending_builtin_scenarios`), deselected by default and run for SPEC 24.2.

### D11 Simulation with the repository's config
`--with-repo-config` calls `load_config(repo)` (exit 2 on schema or secret error), runs `check_role_chains` and `check_profile_kinds` before any scenario (exit 2 naming the path, SCN-SIM-N11), builds fakes for every profile (adapter profiles become `ScriptedAgent`, backend profiles `ScriptedBackend`) and the `FakeForge`, and merges the scenario `config:` on top. Scenario profile keys that are not profile names of the repo config are mapped by role position (the n-th scripted implementer profile drives `roles.implementer[n]`) [I]. Gate commands of the user's config are not executed against the fixture (the fixture has its own unittest gates); their wiring is validated instead: `gates.test.command` non-empty when `tdd.mode != off`, `targeted` contains `{files}` or `{grep}` when set, sandbox mode resolvable [I; SPEC says "validating chains, gates wiring and CI rendering" without defining it]. A guard (`NoRealAgents`) patches `subprocess.Popen` to allow only `git` and the fixture gate command and patches `socket.socket.connect` to raise during the run; a violation fails the scenario.

### D12 Layout additions beyond the implementation map
`src/l4/planner.py`, `src/l4/sim/{types,remote,skeleton,dryrun}.py` and `src/l4/sim/builtin/`.

## Risks / Trade-offs

- The skeleton driver could drift from the real state machine and hide bugs. Mitigation: it handles only the happy edges, reports anything else as `pending`, labels results `driver: skeleton`, and change `implementer-tdd-loop` has a task that re-runs the packaged scenarios with `driver: orchestrator` and deletes the skeleton path once all pass.
- Local mirror types (`SimRunRequest`) may diverge from the final `AgentAdapter` dataclasses (SPEC 8.1). Mitigation: field names copied from SPEC; `agent-factory` aliases them and a contract test compares field sets.
- Integration names of `spec-providers` and `state-vcs-locks` APIs were reconciled by the cross-change review (`collect_units`, `read_ledger`, `fold`); `LiveUnitSource` is still the single adapter point and `StaticUnitSource` keeps planner tests independent.
- Deterministic SHAs depend on identical git behaviour across versions (tree and commit object format is stable) [I]; SCN-SIM-01 compares event sequences, and SHAs are compared only within one machine.
- Scenario YAML under `src/l4/sim/builtin/` deviates from the map's `tests/scenarios/`; documented in README and the manifest docstring.

## Migration Plan

New modules only. Later changes add a YAML file plus manifest entry flip (`file` set) to turn a pending built-in scenario ready. Rollback: remove the `simulate` and `plan` handler strings from `commands.HANDLERS`.
