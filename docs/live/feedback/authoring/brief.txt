Create a Kiro feature spec named `add-low-stock-message` in `.kiro/specs/add-low-stock-message/` for this repository (a small Python library; `src/inventory/stock.py` has `units_short(on_hand: int, wanted: int) -> int`). Feature: a new module `src/inventory/alerts.py` holds `low_stock_message(name: str, on_hand: int) -> str | None`: when `on_hand` is below the low-stock threshold of 5 units it returns the message `Restock <name>: <on_hand> left`, otherwise it returns `None`; a negative `on_hand` raises `ValueError`. Keep it small: exactly two requirements. Requirement 1 is the message, with exactly three acceptance criteria: (1) an `on_hand` below 5 (for example 2 for "bolts") gives `Restock bolts: 2 left`; (2) an `on_hand` of 5 or more (for example 5 and 12) gives `None`; (3) an `on_hand` of 0 gives `Restock <name>: 0 left`. Requirement 2 is input validation, with exactly one acceptance criterion: a negative `on_hand` (for example -1) raises `ValueError`. Criterion M of Requirement N is cited as N.M in tasks.md. Title` with sub-tasks `  - [ ] N.M Title`, each leaf followed by an indented `- _Requirements: X.Y, …_` line. Exactly two parent tasks: task 1 is the message and task 2 the validation.
