# Proposal: fix 1 for add-vat

## Why
The verifier found problems in `add-vat` that this change fixes. The findings are listed below with their ids; each task of this change names the ones it answers.

## What Changes
- F-366420f0 (major): VAT ignores any applied discount code: total_with_vat starts from self.subtotal() and never uses the discounted total that Cart.total() computes. If a discount code has been applied, the VAT total is worked out on the pre-discount amount, so a customer would pay VAT on money they were not charged. The proposal says 'the cart total shown to the customer includes VAT', but the requirement says 'cart subtotal plus VAT', and no scenario covers a discounted cart. Two reasonable implementations give different answers. Example: with 10% off and RO, the committed code gives 121.00, while VAT on the discounted total gives 108.90. [reject...

The code and the tests of `add-vat`.
