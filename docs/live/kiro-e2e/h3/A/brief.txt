Create a Kiro feature spec named `add-small-order-surcharge` in `.kiro/specs/add-small-order-surcharge/` for this repository (a Python pricing library; `src/pricing/cart.py` has `LineItem` and `Cart`, and `Cart.subtotal()` returns the sum of the line totals). Feature: an order whose subtotal is below 20.00 pays a small-order surcharge of 2.00; a subtotal of 20.00 or more pays none (0.00); money is a `Decimal` with two places. A new module `src/pricing/surcharge.py` holds the rule as `small_order_surcharge(subtotal: Decimal) -> Decimal`, and `Cart.small_order_surcharge()` applies it to the cart's subtotal, except that an empty cart pays no surcharge. Keep it small: exactly two requirements. Requirement 1 is the rule, with exactly three acceptance criteria: (1) a subtotal below 20.00 (for example 5.00) gives 2.00; (2) a subtotal of 20.00 or more (for example 20.00 and 35.00) gives 0.00; (3) the subtotal just below the threshold, 19.99, gives 2.00. Requirement 2 is the cart method, with exactly two acceptance criteria: (1) a non-empty cart whose subtotal is below 20.00 gives 2.00 and one whose subtotal is 20.00 or more gives 0.00; (2) an empty cart gives 0.00. Criterion M of Requirement N is cited as N.M in tasks.md. Title` with sub-tasks `  - [ ] N.M Title`, each leaf followed by an indented `- _Requirements: X.Y, …_` line. Exactly two parent tasks: task 1 is the cart method and task 2 the rule module. Task 1 has exactly one required sub-task, 1.1, which implements `Cart.small_order_surcharge()` together with its unit tests (`_Requirements: 2.1, 2.2_`). Task 2 has three sub-tasks in this order: 2.1 (required) creates `surcharge.py` with `small_order_surcharge` together with its unit tests (`_Requirements: 1.1, 1.2_`); 2.2 (required) adds unit tests for the subtotal 19.99 just below the threshold (`_Requirements: 1.3_`), a case the rule written in 2.1 already covers, so 2.2 is expected to need no production change; 2.3 is an optional property-test sub-task written `- [ ]* 2.3` (`_Requirements: 1.1, 1.2_`).
